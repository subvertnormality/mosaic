# Confirmation footer lifetime regression

The controlled native A18 run `8a3011dd1e9142df95c3ef930bb0e1e7` reached the Harmony Delete group confirmation through actual public inputs. Turning E2 while the question owns input correctly left its selection unchanged and displayed K3 CONFIRM / K2 CANCEL. K2 then correctly returned to H04, retained the group and selected Delete group. The normal parent controls were missing: the previous question tooltip still replaced the parent footer. The framebuffer was otherwise the correct ENSEMBLE / CH01 screen with no layout overflow. Its identity and original native failure remain separately retained under `controlled-h04-footer-failure/`.

The UI component regression reproduces the same failure through `ui.enc` / `ui.key`: both Cancel and Confirm return to H04 while `ui_live.view_model().footer` incorrectly remains K3 CONFIRM / K2 CANCEL. `question-footer-red.log` reports exactly those two expected failures, and `question-footer-red-source.json` plus `question-footer-unfixed-ui-live.txt` freeze the original source.

The cause is the unconditional tooltip override in the view model. The modal encoder-refusal feedback uses the shared three-second tooltip. Once the question closes, that feedback no longer describes the visible screen; its remaining timer should not suppress the parent's controls. Other feedback such as APPLIED or a genuine error remains useful and must keep its usual lifetime.
