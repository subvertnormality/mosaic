These two delivery plans were split at the user's request after Paranoia Claude Fable's round-3 review of the combined revision returned NOT-BLOCKED (zero blocking debt, all eight tracked classes closed, two active external claims supported). Round 3's sole minor wording finding is corrected in the nudge plan by giving the requested range one authoritative definition. The split documents themselves have not had a further Fable review. The unchanged reviewed snapshot and reports remain in .paranoia-input/; this is planning only, not implemented or hardware-qualified work.

## 1. Dependency and authoritative requested range

Implement only after [Parameter-lock lead-time foundations](parameter-lock-lead-foundations-plan.md) has reached its independent acceptance decision. Nudge is not required to ship or validate parameter-lock lead time. If only lead0 is qualified, nudge may be developed and qualified with lead0; it must not silently enable an unsupported nonzero lead.

Authoritative requested range: q is a signed fraction of the nominal channel step in [-1/2,+1/2]. All UI, storage and tests derive their bounds from this statement. Store q in 1/48-step increments. Effective output placement is on integer pulses at the existing 96 PPQN and can be narrower than the requested range.

Preserve existing swing/shuffle at zero nudge. This deliberately replaces the original brief's combined straight-grid clamp, because heavy/drunk shuffle can already exceed half a nominal step of straight-grid displacement. The requested nudge is additive relative to the existing feel timeline; ordering is protected by the neighbouring-onset bounds below. No higher PPQN, timer-delayed note path or constant output latency is introduced.

Scope: channel/step nudge, its editor and project persistence, per-occurrence execution and projection changes, integration with qualified parameter lead, and emulator/hardware acceptance. Per-receiver lead overrides and pre-roll remain deferred as specified in the foundations plan.

## 2. Pulse placement and epoch rules

Let B_i be integer pulse onsets from the UNMODIFIED current swing/shuffle rounding recurrence; D_i nominal straight step length in pulses; q_i the requested fraction. Let left_i=(B_prev+B_i)/2 and right_i=(B_i+B_next)/2. Target pulse P_i is nearest integer to B_i+q_i*D_i, ties toward B_i, clamped to [ceil(left_i),floor(right_i)] and the current epoch boundaries. Then P_prev<=P_i<=P_next by common midpoint bounds; zero nudge yields B_i exactly. All feel maps/bases/amounts and fractional division carries must reproduce baseline at q=0. A one-pulse interval prevents displacement toward that neighbour; one-pulse intervals on both sides allow no nonzero displacement. Worked example: for 24-pulse straight steps, -12..12 gives 25 effective positions. This is additive nudge relative to feel, not a clamp of total straight-grid displacement.

Use the foundation's global-pattern epoch fence: no departing occurrence is delayed across reset, and no arriving occurrence is anticipated before reset, even on same-pattern repeats. Master transition callbacks and feel alignment execute first at reset. Clamp first-step backward nudge at Play/Start and every epoch start; report startup/pattern-boundary. This delivery has no pre-roll. Changing division/feel/nudge rebuilds only future unsent occurrences behind a barrier at the last executed pulse/ordinal. If a negative edit's target has passed, apply next occurrence and show late-edit. No duplicate ordinal execution or reordering of committed output.

## 3. Nudge-specific scheduling implementation

Implement a separate per-channel occurrence cursor with base_pulse and target_pulse on m_lattice sprockets, not Sprocket.delay/delay_new. Advance the base recurrence once per base occurrence, independent of where that occurrence executes; P_next-P_i = (B_next-B_i)+(offset_next-offset_i), preventing cumulative phase drift. Keep global/master clocks unchanged. A channel may have two adjacent occurrences due in one pulse: replace the single pending_note slot for this path with a bounded ordered occurrence list and process occurrence waves. Each wave preserves group ordering, locks-before-notes, then post-note work. The next wave processes releases before same-pitch retriggers. Do not let both occurrences overwrite each other's prepared data or collapse one into a single callback. Ordinal tie order is older occurrence first; simultaneous distinct tracks preserve existing sprocket ordering.

Refactor project_onset_pulses and project_onset_occurrence to project from the shared pure base recurrence plus per-occurrence offsets/epoch limits. Remove their phase=onset assumptions for this channel path, NOT the assertions by themselves. Keep variable-division follower semantics separately supported as today; their trigger origin follows the shifted parent and they are not given the parent's offset twice. Delayed musical actions/voice_lifetime resolve occurrence deadlines through the new projection; capture finite gate lengths at trigger using existing musical-length semantics from the shifted origin. Slides interpolate between shifted lock occurrences, with terminal values and wrap/pattern fences explicitly tested. Strum/arp start at shifted trigger, retain existing subsequent spacing and quantisation. Reset/realign/prepare_for_start clear occurrence cursors, speculative offsets and epoch caches; sustain/release cleanup stays separate.

Unit/integration acceptance: all existing projection/slide/arp/release tests at zero nudge; property tests of monotonic pulse ordering and no drift with deterministic seeds; exhaustive feel maps and endpoints; coincident steps with separate RNG decisions/record events; signed nudge start/end slide deadlines; arp followers; fractional gates; live division change. If a timing edit affects a future occurrence, rebuild unsent occurrences with a barrier at the last executed pulse/ordinal, so nothing is scheduled in the past or crosses committed output. A requested negative edit whose target has passed applies next occurrence and displays late-edit. Do not execute the same ordinal twice.

Extend the foundation's parameter preview horizon to cover requested lead plus maximum possible backward nudge, preserving its 64-occurrence cap, queue bounds, one earliest-deadline wakeup and horizon-limit feedback. Use shifted P_i as step/lock anchor times and slide endpoints. Regenerate only unsent bundles when an offset changes; do not consume probability/conditions/RNG during preview. Notes make their decisions at the shifted trigger; document that nudge, unlike lead-only lookahead, intentionally changes those decision times.

Preserve the foundation's shared-receiver rule, byte serialization, conservative protected-anchor policy, generation/commit/resend semantics, clock-change handling and Stop/voice cleanup. At coincident conflicting lock targets only the selected winner's value is promised; retain visible conflict feedback. If nonzero lead is qualified, re-run its acceptance under nudge interactions; it is not redefined in pulses or exempted from lock-gap checks.

## 4. Step editor, persistence and feedback

Hold one/more steps and E3 edits each step's nudge by 1/48 nominal step per detent, bounded to the authoritative section 1 range (equivalently +/-24 detents); with no held steps E3 has no effect and screen says Hold step. K2 with held steps clears their nudge; global mask-clear includes it. No channel-wide default and no device-param slot consumed. Store the integer 1/48-step numerator derived from section 1 in a NEW step_nudge_locks table per channel/song-pattern with explicit schema version, absent/zero meaning zero. Leave existing step_micro_time_masks placeholders uninterpreted; do not silently assign units to old arbitrary values. Add initialization, old-project migration, copy/clear, history undo/redo and save/load. Display requested fraction, effective pulse offset and clamp reason; quantisation explains repeated detents at low resolution. Use existing held-step lock LEDs and highlight selected nudged steps; add deterministic framebuffer/grid captures and semantic assertions.

Extend the foundation's existing Timing page with the quantised reason and selected-step effective pulse offset; do not create a second competing timing screen or change its E2/E3/K2 diagnostic controls. Held-step Nudge editing shows that step's requested fraction, effective offset and clamp reason. Feedback is scheduler prediction/dispatch observation, not measured receiver audio timing. Diagnostic fields remain volatile and are never saved as user choices.

## 5. Independent oracle and hardware decision

Inherit the intended-time event identity, calibration, gap metrics and artifact retention contract from foundations sections 2–3; add offset arithmetic to the fixture-side oracle independently of production projection code. Expectations use P_i and declared tie order, not a uniform grid or actual first-note alignment. Note/gate/clock/transport relationships and lock-gap checks remain explicit. Include false-green synthetic captures for uniform offset, dropped coincident notes, step reordering, wrong value, shortened gates and natural spread misclassified as service time.

For nudge, service groups contain events with the same intended pulse and port; normalize by the minimum nominal channel step in that group. Keep service p99/step <=0.5 and max <=1.0, while also gating total write work in each original nominal-step window at the same limits so singleton groups cannot hide cost. Original four zero-nudge workloads keep their original service groups and all original gates unchanged.

Hardware metrics retain event p99 <=10 ms with the existing one-stalled-step treatment, event max <=50 ms, final phase <=20 ms, intended-interval jitter p95 <=5 ms and max <=10 ms. Lock-gap metrics and capture uncertainty remain exactly those in the foundations contract for qualified lead modes. Report CPU, writes, bytes and worst pulse work; do not assert hardware equivalence from controlled virtual time.

Freeze manifest, fixture identities, source SHA, seed/order and timing-contract version before trials. Use ten paired/interleaved windows of 80 intended step occurrences per workload/lead/nudge-profile cell; all applicable gates must pass in every window. Retain every failed/invalid window and reason; only capture/calibration/source-identity failures invalidate runs, never a timing failure. Use foundations section 3's conservative lead0 distribution comparison and exact zero-nudge controlled-time byte/timeline parity against the accepted foundations revision.

Nudge go/no-go: profile set is zero, alternating endpoints, staggered 16-channel offsets, coincident neighbours/same-pitch, and all feel-map endpoint collisions at relevant divisors including x16. Each must pass unchanged intended-time jitter/service and the repeated-window rules immediately above at leads 0/25/50 where that lead mode has qualified. If full nudge fails, stop its delivery. A smaller range/resolution is a NEW experiment and contract requiring the same gates and reviewed UI expectations; the immediate fallback is nudge disabled, saved requests preserved but effective zero with unavailable feedback. No gate widening or implied guarantee that coarser nudge will pass. The foundations delivery remains independently shippable. Nudge may qualify at lead0 alone, explicitly documenting nonzero-lead unavailability.
